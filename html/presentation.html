02 · 문제

기존 자세 교정기는 센서 1개, 기준도 모두 동일

센서 1개의 한계

  • 상체 기울기만 측정
  • 권장 동작인 힙 힌지에도 경고 (오알림)
  • 허리가 뜬 채 뒤로 기댄 자세는 놓침

모두에게 같은 기준

  • 탈출 부위마다 피해야 할 동작이 다름
  • 요추: 허리 말아 굽히기
  • 경추: 목 앞으로 빼기

프로필 = 진단명이 아니라 '피해야 할 동작'. 시스템은 진단하지 않고, 받은 안내를 그대로 입력한다.

03 · 핵심 원리

곡률은 두 점의 기울기 차이다

요추 굴곡

위 센서만 더 기욺
굴곡각 큼 → 알림

힙 힌지

두 센서가 같이 기욺
굴곡각 ≈ 0 → 정상

구간 굴곡각 = (θ상부 − θ하부) − 중립 보정값

왜 2개인가

θ상부 = 골반 기울기 + 요추 굴곡
센서 1개는 식 1개, 미지수 2개. S1 센서가 골반 기울기를 직접 재서 풀어 줍니다.

배치

상부 T12/L1 (요추 위쪽 끝)
하부 S1 (천골)
한 MCU가 같은 타이머로 읽어 동기화 문제 없음

06 · 접근

하드웨어 전에, 시뮬레이션과 공개 데이터로 먼저

왜 이 순서인가

부품을 사고 데이터를 모으기 전에 파이프라인과 평가 방법을 먼저 끝내면, 실데이터가 들어오는 순간 바로 검증할 수 있습니다.

MuJoCo 시뮬레이터

근골격 모델에서 센서 두 점의 신호를 생성. 센서가 밀리는 상황(2~6°, 스트레스 12°)도 재현.

HARTH 사전학습

공개 활동 데이터 22명으로 '움직임' 표현을 먼저 학습한 뒤 우리 과제로 미세조정.

평가 설정

  • 학습과 겹치지 않는 시뮬 사용자로 평가
  • 보통 조건 vs 스트레스(센서 12° 밀림)
  • 지표: 재현율, 오알림 횟수 / 시간
  • CNN은 시드 6개 반복, 평균 ± 표준편차

주의

아래 결과는 전부 시뮬레이션 데이터 기준입니다. 실제 사람에게도 통하는지는 다음 단계에서 확인합니다.

07 · 결과 ① — 가설 1

센서 2개로 오알림이 2.08 → 0.02회/시간

재현율 (진짜 나쁜 자세를 잡아낸 비율, 높을수록 좋음)

H1 지지됨

같은 룰 방식에서 센서만 1개 → 2개로 바꿔도 오알림은 약 100배 감소, 재현율은 33% → 90%.

스트레스 조건에서도 방향은 같음: 오알림 2.01 → 0.66, 재현율 29% → 73%.

08 · 결과 ② — 가설 2

룰 vs CNN: 보통에선 룰이 충분, 스트레스에선 CNN이 약간 우세

엔진보통 재현율보통 오알림/h스트레스 재현율스트레스 오알림/h학습 시간
센서 1개 룰 (v0a)33%2.0829%2.01—
센서 2개 룰 (v0b)89.8%0.0272.5%0.66—
CNN 처음부터91.4%0.15 ± 0.1377.4%0.74 ± 0.1822.6분
CNN + HARTH 사전학습90.0%0.09 ± 0.1075.5%0.64 ± 0.2111.6분

H2는 일부만

CNN은 보통 조건에서 오알림을 줄이지 못했고(룰 0.02 vs CNN 0.09~0.15), 센서가 밀리는 스트레스에서 재현율이 3–5%p 높았다.

사전학습의 이득은 '속도'

정확도는 비슷하고 학습 시간이 절반. 오알림은 처음부터보다 약간 적다(스트레스 0.64 vs 0.74).

CNN: 시뮬 실험실 32명 + 하루 생활 160명, 25 epoch, 시드 6개 평균 ± 표준편차. 오알림 표준편차가 커서 CNN 간 차이는 확정적이지 않음.

09 · 해석

확실한 것과 아직 모르는 것

확실한 것

  • 센서 2개가 힙 힌지 오알림을 거의 없앤다 (시뮬 기준)
  • 사전학습은 학습 시간을 절반으로 줄인다
  • 전체 파이프라인이 하드웨어 없이 끝까지 돈다

아직 모르는 것

  • 시뮬 → 실제에서도 성립하는가 (sim-to-real)
  • 정지 자세는 룰로 충분, ML 이득은 센서가 밀릴 때만?
  • 옷 위·재착용 시 부착 편차의 실제 크기

가설이 틀려도 그대로 보고한다는 원칙으로 설계했고, 현재 결과는 "룰이 강한 기준선이고 ML은 어려운 조건에서만 이득"에 가깝습니다.

10 · 다음 단계

실제 센서 데이터로 검증하러 간다

① 하드웨어

ESP32 + MPU-6050 ×2, 점퍼 연결(납땜 없음), 약 2–3만원. 펌웨어는 이미 작성 완료.

② 본인 데이터 수집

허리디스크 환자인 제가 직접 착용. record.py → replay 왕복 점검.

③ sim-to-real 점검

시뮬 vs 실측 분포 차이를 확인하고 보정·미세조정.

④ 자유 생활 · 확장

하루 착용 테스트, 휴대폰 푸시 알림, 프로필 전환 데모 리허설.

표현 원칙: 치료·진단·재활이 아니라 "피해야 할 자세 습관 알림". 의료기기가 아닙니다.

데모 · 마무리

센서가 하나 더 있으면, 자세 알림이 정확해진다

python -m ml.app.record --fake --live --engine v0b
python -m ml.app.replay --profile lumbar_flexion_guard --engine cnn

하드웨어 없이 가상 센서로 실시간 판정과 프로필 전환을 보여드립니다. 질문 받겠습니다.
